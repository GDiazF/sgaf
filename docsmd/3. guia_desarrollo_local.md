# Guía de Configuración para Desarrollo Local - SGAF

Este documento describe los pasos necesarios para levantar el sistema SGAF en un entorno de desarrollo local (Windows/macOS/Linux) sin utilizar Docker.

## 1. Requisitos Previos

Asegúrate de tener instalados los siguientes componentes:
- **Python 3.10 o superior**
- **Node.js 18 o superior** (incluye npm)
- **Git**

---

## 2. Preparación del Backend (Django)

El backend gestiona la lógica de negocio y la base de datos SQLite.

1.  **Navegar a la carpeta del backend:**
    ```powershell
    cd backend
    ```

2.  **Crear y activar un entorno virtual:**
    ```powershell
    # Crear entorno
    python -m venv venv

    # Activar (Windows)
    .\venv\Scripts\activate

    # Activar (Linux/macOS)
    source venv/bin/activate
    ```

3.  **Instalar dependencias:**
    ```powershell
    pip install -r requirements.txt
    ```

4.  **Configurar Variables de Entorno (.env):**
    Crea un archivo llamado `.env` dentro de la carpeta `backend/` con el siguiente contenido base:
    ```env
    DEBUG=True
    SECRET_KEY=django-insecure-local-dev-key
    ALLOWED_HOSTS=localhost,127.0.0.1
    CORS_ALLOWED_ORIGINS=http://localhost:5173
    CSRF_TRUSTED_ORIGINS=http://localhost:5173

    # Sidecar firma-dep (obligatorio para probar firma)
    FIRMA_DEP_URL=http://127.0.0.1:4010/api/v1
    FIRMA_DEP_CLIENT_ID=sgaf-backend
    FIRMA_DEP_API_KEY=dev-key
    FIRMAGOB_ENTITY=Servicio Local de Educación Pública de Iquique
    FIRMAGOB_PURPOSE=Propósito General
    ```
    Las credenciales FirmaGob (Token Key / Secret) van en `services/firma-dep/.env`, no en `backend/.env`.
    *Nota: Al no definir `DB_NAME`, el sistema usará SQLite automáticamente.*

    > [!IMPORTANT]
    > - **Local:** el `.env` va en `backend/.env` (aquí corre `manage.py`).
    > - **Producción (Docker):** el `.env` va en la **raíz** del repo; no confundir con `backend/.env`.
    > - Guarda el archivo en **UTF-8** (no UTF-16). Token/Secret nunca van a Git.
    > - Checklist de producción: `docs/1. guia_primerdespliegue_docker.md` y `docs/2.2 guia_actualizacion_sistema.md`.

5.  **Base de Datos (SQLite):**
    Asegúrate de que el archivo `db.sqlite3` se encuentre en la raíz de la carpeta `backend/`. Si es una instalación nueva, puedes generar las tablas con:
    ```powershell
    python manage.py migrate
    ```

6.  **Iniciar Servidor de Desarrollo:**
    ```powershell
    python manage.py runserver 8000
    ```
    El API estará disponible en `http://localhost:8000/api`.

---

## 3. Preparación del Frontend (Vite + React)

El frontend se comunica con el backend mediante peticiones HTTP.

1.  **Navegar a la carpeta del frontend:**
    ```powershell
    cd frontend
    ```

2.  **Instalar dependencias de Node:**
    ```powershell
    npm install
    ```

3.  **Configurar Variables de Entorno (.env):**
    Crea un archivo llamado `.env` dentro de la carpeta `frontend/` para indicar la ruta del API:
    ```env
    VITE_API_URL=http://localhost:8000/api
    ```

4.  **Iniciar Servidor de Desarrollo:**
    ```powershell
    npm run dev
    ```
    La interfaz estará disponible en `http://localhost:5173`.

## 3.1. Firma digital (sidecar firma-dep, sin Docker)

La firma electrónica **no** llama a FirmaGob desde Django. Corre un microservicio NestJS en el puerto **4010** (`services/firma-dep`).

### Requisitos
- Node.js **20.x** y npm 10.x
- Una sola vez: `cd services/firma-dep` → `npm install`
- Copiar `services/firma-dep/.env.example` → `services/firma-dep/.env` y completar Token/Secret (CERT o producción). Ver comentarios del `.env.example`.

### Variables en `backend/.env`
```env
FIRMA_DEP_URL=http://127.0.0.1:4010/api/v1
FIRMA_DEP_CLIENT_ID=sgaf-backend
FIRMA_DEP_API_KEY=dev-key
```
Las llaves FirmaGob (`FIRMA_GOB_API_TOKEN_KEY` / `FIRMA_GOB_SECRET`) van **solo** en `services/firma-dep/.env`.

### Terminal 3 (firma-dep)
```powershell
cd services\firma-dep
npm run start:dev
```
Debe mostrar `http://localhost:4010/api/v1`. Health: `http://127.0.0.1:4010/api/v1/health`  
Swagger: `http://127.0.0.1:4010/docs`

### Prueba recomendada (antes de SGAF)
1. Colección Postman en `services/firma-dep/postman/firma-dep.postman_collection.json` contra `localhost:4010`.
2. CERT atendida: RUT `11.111.111-1` + OTP sandbox del manual (si usás llaves sandbox del manual; con token de app SLEP CERT puede fallar el RUT de prueba).
3. CERT desatendida: RUT `22.222.222-2` sin OTP.
4. Luego en SGAF: `/firma-prueba` (requiere permiso `can_probar_firma`) y bandeja RC en `/firma` (requiere `can_firmar` + grupo firmante). Ver permisos abajo.

### Permisos (Admin → Roles)

| Permiso | Acceso |
|---------|--------|
| `firma_digital.can_firmar` | Bandeja `/firma` (+ funcionario activo + grupo «firmantes») |
| `firma_digital.can_probar_firma` | Laboratorio `/firma-prueba` (independiente; ideal solo para TI) |

Tras asignar roles: **cerrar sesión y volver a entrar**.

En **producción**, los RUT sandbox del manual CERT no aplican si `FIRMA_GOB_ENVIRONMENT=production`.

## 4. Resumen de Flujo de Trabajo

Para trabajar diariamente en el sistema:
1.  **Terminal 1 (Backend):** `cd backend` → activar venv → `python manage.py runserver`
2.  **Terminal 2 (Frontend):** `cd frontend` → `npm run dev`
3.  **Terminal 3 (firma-dep):** `cd services\firma-dep` → `npm run start:dev` (solo si vas a firmar documentos)

Los tres servicios deben estar corriendo simultáneamente para probar firma digital.
