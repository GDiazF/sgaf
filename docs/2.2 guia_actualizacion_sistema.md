# Guía 2.2: Actualización del Sistema desde GitHub

Actualizar el servidor con el flujo automatizado (`./scripts/deploy.sh`). El script sincroniza IP/hostname en `.env`, construye contenedores, aplica migraciones y estáticos.

## Flujo rápido (recomendado)

```bash
cd ~/sgaf
git pull origin reingenieria
./scripts/deploy.sh --backup
```

| Opción | Uso |
|--------|-----|
| `--backup` | Respaldo SQL en `~/sgaf_backups/` antes de desplegar |
| `--quick` | Sin `docker compose build` (solo reinicia contenedores). **No** actualiza CSS/JS del frontend ni imágenes Docker; use el flujo completo si cambió UI o firma-dep. |
| `--extra-hosts dominio.local,otro` | Agrega hosts extra a `ALLOWED_HOSTS` |

> **Cambios de interfaz (menú, modales, bandeja de firmas):** hace falta build del frontend. `./scripts/deploy.sh` (sin `--quick`) o `docker compose up -d --build frontend`.

## 1. Respaldo manual (opcional)

Si no usas `--backup`:

```bash
docker exec sgaf_db_prod pg_dump -U sgaf_user sgaf_db > ~/respaldo_preventivo.sql
cp -r ~/sgaf/media ~/media_preventivo
```

> Ajusta `sgaf_user` / `sgaf_db` si tu `.env` usa otros nombres.

## 2. Qué hace `deploy.sh` automáticamente

1. **`setup_env.sh`** — crea `.env` si no existe (nunca lo reemplaza).
2. **`sync_env_network.sh`** — detecta IP y hostname (`svtest`, etc.) y actualiza:
   - `ALLOWED_HOSTS`
   - `CORS_ALLOWED_ORIGINS`
   - `CSRF_TRUSTED_ORIGINS`
   - `SGAF_PUBLIC_URL`, `FRONTEND_URL`, `VITE_API_URL`
3. Claves nuevas de `.env.example` → `.env` (sin tocar secretos ya configurados).
4. `docker compose up -d --build`
5. `migrate` + `collectstatic`

**No modifica:** `SECRET_KEY`, `DB_PASSWORD`, tokens FirmaGob, `API_CLIENT_KEYS`.

## 3. Primera instalación con firma-dep

```bash
cd ~/sgaf
git clone -b reingenieria https://github.com/GDiazF/sgaf.git sgaf
cd sgaf
chmod +x scripts/*.sh scripts/lib/*.sh
./scripts/setup_env.sh
nano .env    # pegar FIRMA_GOB_API_TOKEN_KEY, FIRMA_GOB_SECRET, API_CLIENT_KEYS
./scripts/deploy.sh
```

Un solo `.env` en la raíz para Django y firma-dep.

Contenedores relevantes: `sgaf_backend_prod`, `sgaf_frontend_prod`, `sgaf_firma_dep`, `sgaf_db_prod`.

## 4. Firma digital (bandeja, RC, laboratorio)

### Arquitectura

`Django` → `firma-dep` (`FIRMA_DEP_URL`, puerto 4010 interno) → API FirmaGob.

### Permisos de usuario (Admin → Roles)

| Permiso | Menú / función |
|---------|----------------|
| **Puede firmar digitalmente** (`firma_digital.can_firmar`) | Bandeja de firmas (`/firma`) |
| **Puede usar firma digital (prueba)** (`firma_digital.can_probar_firma`) | Laboratorio `/firma-prueba` (solo TI/admin) |

Además de `can_firmar`, el firmante operativo debe:

1. Tener **funcionario** vinculado y activo.
2. Pertenecer a un **grupo de firmantes** (`Funcionarios → Grupos`, marca «Grupo de firmantes»).
3. Tener **sello de firma** configurado (funcionario / unidad / departamento).

Tras asignar roles o permisos, el usuario debe **cerrar sesión y volver a entrar**.

### Recepciones conformes → bandeja

En `/services/payments?tab=recepciones`, RC en estado **Emitida** con **firmante** asignado → **Enviar a firmar** (paquete PDF RC + anexos).

### Producción vs CERT

- **Producción** (`FIRMA_GOB_ENVIRONMENT=production`): RUT real del firmante + OTP de la RA. Los RUT sandbox `11.111.111-1` / `22.222.222-2` **no** funcionan.
- **CERT** (`test`): solo laboratorio; RUTs del manual FirmaGob.

### Variables críticas en `.env` (raíz)

```env
FIRMA_DEP_URL=http://firma-dep:4010/api/v1
FIRMA_DEP_CLIENT_ID=sgaf-backend
FIRMA_DEP_API_KEY=...          # mismo valor que en API_CLIENT_KEYS
API_CLIENT_KEYS=sgaf-backend:...
API_ALLOW_PRIVATE_NETWORKS=true
FIRMA_GOB_API_TOKEN_KEY=...
FIRMA_GOB_SECRET=...
FIRMA_GOB_ENVIRONMENT=production
```

`FIRMA_DEP_API_KEY` y la parte derecha de `API_CLIENT_KEYS` deben coincidir.

## 5. Migraciones

> **NUNCA** ejecute `makemigrations` en producción. Solo `migrate` (incluido en `deploy.sh`).

Si `migrate` falla por ramas divergentes, debe existir en Git una migración `merge_*`; haga `git pull` y vuelva a `./scripts/deploy.sh`.

Migraciones recientes de firma digital (ej. `firma_digital.0005_can_probar_firma_perm`) se aplican con el `migrate` del deploy.

## 6. Solución de problemas

### Login: `Bad Request (400)` HTML sin JSON

Host no permitido. En el servidor:

```bash
./scripts/sync_env_network.sh
docker compose up -d backend
```

O use la URL que muestra el script (`SGAF_PUBLIC_URL`).

### Firma: «No autorizado» o menú de bandeja oculto

Revise permisos, grupo de firmantes y funcionario activo (sección 4). Re-login obligatorio.

### Firma: error al «Enviar a firmar» RC

Confirme que la RC tiene firmante, está emitida y que backend está actualizado (`git pull` + `docker compose restart backend`).

### Firma-dep no responde desde backend

```bash
docker compose logs -f firma-dep
docker compose up -d --build firma-dep
```

Verifique `API_ALLOW_PRIVATE_NETWORKS=true` en `.env` y que `API_CLIENT_KEYS` coincide con `FIRMA_DEP_API_KEY`.

### `git pull` con conflictos

```bash
git checkout -- backend/solicitudes_reservas/.email_counter.json
git pull origin reingenieria
```

Migración local duplicada:

```bash
rm backend/procedimientos/migrations/0005_alter_procedimiento_archivo.py  # según el error
git pull origin reingenieria
```

### Ver logs

```bash
docker compose logs -f backend
docker compose ps
```

### Contraseña de admin

```bash
docker exec -it sgaf_backend_prod python manage.py changepassword admin
```
