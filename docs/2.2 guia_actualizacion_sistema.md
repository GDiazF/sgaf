# Guía 2.2: Actualización del Sistema desde GitHub

Esta guía detalla los pasos para actualizar el servidor de producción con la última versión del código, garantizando la seguridad de los datos.

## 1. 🛡️ PASO PREVIO: Respaldo de seguridad
Nunca actualices sin tener una copia fresca de los datos. Ejecuta estos comandos en la terminal de Ubuntu:

> [!WARNING]
> ⚠️ **ATENCIÓN:** Si en tu servidor configuraste un usuario o nombre distinto para la BD, debes cambiar `sgaf_user` y `sgaf_db` en este comando.

```bash
# Respaldo de Base de Datos
docker exec sgaf_db_prod pg_dump -U sgaf_user sgaf_db > ~/respaldo_preventivo.sql

# Respaldo de Media (Fotos/Archivos)
cp -r ~/sgaf/media ~/media_preventivo
```

## 2. DESCARGA: Obtener el nuevo código
Entra a la carpeta del proyecto y descarga los cambios de GitHub:

```bash
cd ~/sgaf
git pull origin reingenieria
```

### ⚠️ Solución de Conflictos Comunes

**1. Cambios automáticos en archivos locales**
Si el `git pull` falla por archivos como `.email_counter.json`, ejecuta:
```bash
# Limpiar cambios locales automáticos
git checkout -- backend/solicitudes_reservas/.email_counter.json
# Intentar el pull de nuevo
git pull origin reingenieria
```

**2. Archivos de migración conflictivos**
Si el `git pull` muestra un error indicando que *archivos sin seguimiento serán sobrescritos* (ej. `backend/procedimientos/migrations/0005_...py`), significa que existe una migración local con el mismo nombre que una del servidor. Bórrala y vuelve a intentar:
```bash
# Eliminar la migración local conflictiva (ajusta la ruta según el error)
rm backend/procedimientos/migrations/0005_alter_procedimiento_archivo.py
# Intentar el pull de nuevo
git pull origin reingenieria
```


## 3. DESPLIEGUE: Aplicar los cambios
Para que el nuevo código empiece a funcionar, debemos reconstruir los contenedores:

```bash
docker compose up -d --build
```
*Este comando reemplaza el código pero **mantiene intactos** tus datos de la base de datos y la media.*

## 4. ⚙️ BASE DE DATOS: Migraciones y Estáticos
Una vez que los contenedores estén arriba, es **obligatorio** aplicar los cambios en la base de datos y actualizar los archivos visuales.

> [!CAUTION]
> ⚠️ **REGLA DE MIGRACIONES:**
> * **NUNCA** ejecutes `makemigrations` en el servidor de producción. Las migraciones deben crearse **localmente** en tu máquina de desarrollo, confirmarse en Git (`git commit`) y subirse al repositorio.
> * **NUNCA** modifiques o elimines archivos de migración que ya hayan sido subidos y aplicados en producción. Si necesitas realizar un cambio en un modelo, genera una nueva migración con `makemigrations` de forma local y súbela.
> * Ejecutar `makemigrations` en producción causa desincronización entre la base de datos y los archivos de Git, lo que provoca errores 500 difíciles de diagnosticar.

Ejecuta únicamente los siguientes comandos para aplicar las migraciones existentes y recolectar los estáticos:

```bash
# 1. Aplicar cambios en la base de datos (Migraciones ya creadas y subidas a Git)
docker exec -it sgaf_backend_prod python manage.py migrate

# 2. Actualizar archivos estáticos (CSS, JS del admin)
docker exec -it sgaf_backend_prod python manage.py collectstatic --noinput
```

## 5. 🔑 VERIFICACIÓN: Usuarios y Acceso
Si necesitas verificar que los usuarios existen o si olvidaste la contraseña:

> [!TIP]
> 📌 **CONSEJO:** Si usaste un usuario distinto en el archivo `.env`, cambia `sgaf_user` y `sgaf_db` en el comando.

**Ver lista de usuarios:**
```bash
docker exec -it sgaf_backend_prod psql -U sgaf_user -d sgaf_db -c "SELECT username FROM auth_user;"
```

**Cambiar contraseña de administrador:**
```bash
docker exec -it sgaf_backend_prod python manage.py changepassword admin
```

---
> [!IMPORTANT]
> Si el sistema no responde después del build, revisa los logs con: `docker compose logs -f backend`
