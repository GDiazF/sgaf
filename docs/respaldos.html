Respaldos

Proteger base de datos y archivos. Cada pestaña explica qué hace cada paso y por qué.

  1. Paso 1 — Respaldo al actualizar (con deploy) 
    cd ~/sgaf
./scripts/deploy.sh --backup

    Respalda la BD y luego actualiza el sistema en un solo flujo.

    Por qué Es la forma más segura de actualizar: siempre tiene un .sql del momento justo antes de migraciones o cambios de código. El archivo queda en ~/sgaf_backups/respaldo_YYYYMMDD_HHMMSS.sql.

  2. Paso 2 — Respaldo solo BD (sin actualizar) 
    cd ~/sgaf
./scripts/backup_db.sh

    Genera respaldo en ./respaldos/ dentro del proyecto.

    Por qué Cuando quiere una copia de seguridad sin desplegar cambios (ej. antes de una operación arriesgada en la web). El script rota automáticamente archivos de más de 30 días para no llenar el disco.

  1. Paso 1 — Crear carpeta de respaldos 
    mkdir -p ~/sgaf_backups

    Asegura que existe un lugar fijo para guardar copias.

    Por qué Sin la carpeta, el redirección > archivo.sql puede fallar. Centralizar en ~/sgaf_backups facilita encontrar respaldos después.

  2. Paso 2 — Exportar base de datos 
    STAMP=$(date +%Y%m%d_%H%M%S)
docker exec sgaf_db_prod pg_dump -U sgaf_user sgaf_db \
  > ~/sgaf_backups/respaldo_${STAMP}.sql
ls -lh ~/sgaf_backups/respaldo_${STAMP}.sql

    Volcar todo PostgreSQL a un archivo SQL con marca de tiempo.

    Por qué pg_dump dentro del contenedor accede a la BD en ejecución. La fecha en el nombre evita confusiones. ls -lh verifica que el archivo tiene tamaño razonable (no 0 bytes).

  3. Paso 3 — Copiar archivos media 
    cp -a ~/sgaf/media ~/sgaf_backups/media_${STAMP}

    Duplicar fotos, PDFs y documentos subidos por usuarios.

    Por qué El respaldo de BD no incluye archivos en disco: solo registros. Los PDF firmados, fotos de funcionarios, etc. viven en ~/sgaf/media. Sin copiar media, recuperaría datos pero perdería archivos.

  4. Paso 4 — (Opcional) Comprimir 
    gzip ~/sgaf_backups/respaldo_${STAMP}.sql

    Reduce tamaño para guardar o subir a la nube.

    Por qué Un .sql de producción puede ser grande. gzip ahorra espacio en disco y acelera subidas a Google Drive.

Script del repo: scripts/respaldo_automatico_sgaf.sh. Copia BD y media a Google Drive vía rclone.

  1. Paso 1 — Instalar rclone 
    sudo apt update
sudo apt install rclone -y

    Herramienta de línea de comandos para sincronizar con la nube.

    Por qué El servidor no tiene interfaz gráfica para Google Drive. rclone permite subir y sincronizar archivos desde scripts y cron sin abrir el navegador en Ubuntu.

  2. Paso 2 — Vincular cuenta Google Drive 
    rclone config

    Crear un “remote” llamado drivesoporteti (nombre que usa el script).

    Por qué rclone necesita credenciales OAuth guardadas en el servidor. El nombre drivesoporteti debe coincidir con DRIVE_REMOTE en el script; si usa otro nombre, debe cambiarlo también en el script.

    • n → nuevo remote · nombre: drivesoporteti
    • Tipo drive · Client ID/Secret: vacío (Enter)
    • Scope 1 · Auto config: n (SSH sin navegador)
    • En Windows: rclone authorize "drive" "clave..." → pegar JSON en Ubuntu
    • Shared Drive: n · Guardar: y · Salir: q
  3. Paso 3 — Ajustar rutas en el script 
    nano ~/sgaf/scripts/respaldo_automatico_sgaf.sh
    BACKUP_DIR="/home/tu_usuario/sgaf/backups"
MEDIA_DIR="/home/tu_usuario/sgaf/media"

    Reemplazar tu_usuario con su usuario Linux real.

    Por qué El script en Git tiene rutas de ejemplo (svtest). En otro servidor las carpetas están bajo /home/<su_usuario>/sgaf/. Rutas incorrectas hacen que el respaldo falle o guarde en el lugar equivocado.

  4. Paso 4 — Permisos y formato Linux 
    sed -i 's/\r$//' ~/sgaf/scripts/*.sh
chmod +x ~/sgaf/scripts/respaldo_automatico_sgaf.sh

    Corregir finales de línea Windows y habilitar ejecución.

    Por qué Archivos editados en Windows traen \r\n; en Linux eso provoca \r: command not found. Sin chmod +x, bash no puede ejecutar el script (ni manual ni desde cron).

  5. Paso 5 — Probar una ejecución manual 
    bash ~/sgaf/scripts/respaldo_automatico_sgaf.sh

    Verificar que sube a Drive antes de programar cron.

    Por qué Si falla aquí (rclone, docker, rutas), fallará también en cron. Confirme en Google Drive las carpetas SGAF_Backups y SGAF_Media. El script comprime BD, hace rclone copy/sync y borra copias > 14 días.

Requiere rclone y script configurados (pestaña Google Drive).

  1. Paso 1 — Abrir el programador de tareas 
    crontab -e

    Edita la lista de comandos que Linux ejecuta automáticamente.

    Por qué Los respaldos manuales dependen de que alguien recuerde hacerlos. cron ejecuta el script en horarios fijos sin intervención humana.

  2. Paso 2 — Agregar horarios de respaldo 
    # Respaldos SGAF: 9:00 y 18:00 todos los días
0 9 * * * /home/tu_usuario/sgaf/scripts/respaldo_automatico_sgaf.sh >> /home/tu_usuario/backup_log.txt 2>&1
0 18 * * * /home/tu_usuario/sgaf/scripts/respaldo_automatico_sgaf.sh >> /home/tu_usuario/backup_log.txt 2>&1

    Dos respaldos diarios: mañana y tarde. Cambie tu_usuario.

    Por qué 0 9 * * * = minuto 0, hora 9, todos los días. Dos puntos en el día limitan la pérdida de datos si falla el servidor entre respaldos. > backup_log.txt 2>&1 guarda salida y errores para diagnosticar.

  3. Paso 3 — Guardar y salir del editor

    En nano: Ctrl+O, Enter, Ctrl+X.

    Por qué Las líneas no se activan hasta guardar crontab. Si cierra sin guardar, no habrá respaldos automáticos.

  4. Paso 4 — Verificar que cron registró las tareas 
    crontab -l

    Lista las entradas activas de su usuario.

    Por qué Confirma que las dos líneas aparecen y las rutas son correctas. Tras el primer horario programado, revise cat ~/backup_log.txt.

Formato cron 
minuto  hora  día  mes  día_semana  comando
0       9     *    *    *             respaldo...

Precaución Restaurar reemplaza los datos actuales. Respalde el estado actual antes de importar uno antiguo.
  1. Paso 1 — Restaurar base de datos desde archivo local 
    # Comprimido:
gunzip -c ~/sgaf_backups/respaldo.sql.gz | \
  docker exec -i sgaf_db_prod psql -U sgaf_user -d sgaf_db

# Sin comprimir:
cat ~/sgaf_backups/respaldo.sql | \
  docker exec -i sgaf_db_prod psql -U sgaf_user -d sgaf_db

    Importar el SQL dentro del contenedor PostgreSQL.

    Por qué psql ejecuta las instrucciones del dump y reconstruye tablas y datos. Se usa cuando una actualización falló o se borraron datos por error.

  2. Paso 2 — Restaurar media 
    cp -a ~/sgaf_backups/media_respaldo/* ~/sgaf/media/

    Devolver archivos subidos al directorio activo.

    Por qué La BD restaurada puede referenciar archivos que solo existen en la copia de media/. Sin este paso vería registros pero PDFs o imágenes rotas.

  3. Paso 3 — Restaurar desde Google Drive 
    rclone copy drivesoporteti:SGAF_Backups/backup_sgaf_2026-01-01_09-00.sql.gz ~/restaurar/
gunzip -c ~/restaurar/backup_sgaf_2026-01-01_09-00.sql.gz | \
  docker exec -i sgaf_db_prod psql -U sgaf_user -d sgaf_db

    Bajar el respaldo de la nube y luego importarlo.

    Por qué Si el servidor perdió discos o no tiene copias locales, la nube es el único origen. rclone copy trae el archivo; el resto es igual que restaurar local.
