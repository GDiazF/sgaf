# Guía de Despliegue y Orquestación Docker - SGAF

Este manual describe el proceso para desplegar el sistema SGAF desde un repositorio de Git hasta un servidor de producción.

## 1. Descarga del Código
Desde el directorio home del usuario:
```bash
git clone -b reingenieria https://github.com/GDiazF/sgaf.git
cd sgaf
```

## 2. Configuración del Ambiente (.env)
El sistema utiliza un archivo `.env` en la raíz para separar las credenciales del código fuente.
```bash
nano .env
```

### 🔧 Configuración utilizada (Ejemplo para IP 10.0.100.99):
> [!WARNING]
> ⚠️ **ATENCIÓN AL CAMBIAR SERVIDOR:** Debes reemplazar obligatoriamente `10.0.100.99` por la nueva IP de tu servidor en TODAS las variables de red de este bloque (`ALLOWED_HOSTS`, `CORS`, `CSRF` y `VITE_API_URL`).

Puedes usar este bloque como plantilla base:

```env
# --- IDENTIDAD DEL AMBIENTE ---
DEBUG=False
SECRET_KEY=django-insecure-z*#p5r!d1@9z9(s6-u*f-1o#p6_r8_m=u4#0r!v9t_=2t_1j_8

# --- RED Y SEGURIDAD ---
ALLOWED_HOSTS=10.0.100.99,localhost,127.0.0.1
CORS_ALLOWED_ORIGINS=http://10.0.100.99:8080
CSRF_TRUSTED_ORIGINS=http://10.0.100.99:8080

# --- BASE DE DATOS (POSTGRESQL EN DOCKER) ---
DB_NAME=sgaf_db
DB_USER=sgaf_user
DB_PASSWORD=sgaf_contrasenia_secreta_2026
DB_HOST=db
DB_PORT=5432

# --- URL DE LA API (FRONTEND COMUNICATION) ---
VITE_API_URL=http://10.0.100.99:8080/api

# --- LÍMITES ---
EMAIL_DAILY_LIMIT=200

# --- FIRMA-DEP (sidecar NestJS :4010) ---
# Docker: todo en este .env (ver también bloque FIRMA_GOB_* abajo).
FIRMA_DEP_URL=http://firma-dep:4010/api/v1
FIRMA_DEP_CLIENT_ID=sgaf-backend
FIRMA_DEP_API_KEY=dev-key
API_CLIENT_KEYS=sgaf-backend:dev-key
FIRMA_GOB_ENABLED=true
FIRMA_GOB_ENVIRONMENT=production
FIRMA_GOB_API_TOKEN_KEY=PEGAR_TOKEN_KEY_RA
FIRMA_GOB_SECRET=PEGAR_SECRET_RA
FIRMA_GOB_DEFAULT_ENTITY=Servicio Local de Educación Pública de Iquique
FIRMA_GOB_PURPOSE_ATTENDED=Propósito General
# Etiquetas UI (opcional)
FIRMAGOB_ENTITY=Servicio Local de Educación Pública de Iquique
FIRMAGOB_PURPOSE=Propósito General
```

### Firma digital en producción (checklist)

> [!IMPORTANT]
> Un solo `.env` en la **raíz** (`~/sgaf/.env`) para Django y firma-dep. **No** uses `backend/.env` en el servidor.

**Nueva instalación:**

```bash
cd ~/sgaf
./scripts/setup_env.sh
nano .env
chmod 600 .env
```

1. Pegar `FIRMA_GOB_API_TOKEN_KEY` y `FIRMA_GOB_SECRET` de la RA.
2. `API_CLIENT_KEYS=sgaf-backend:tu_api_key` igual que `FIRMA_DEP_CLIENT_ID` + `FIRMA_DEP_API_KEY`.
3. `docker compose up -d --build`.

**Actualizaciones:** `git pull` no modifica tu `.env`. Solo vuelve a editar si el repo añade variables nuevas en `.env.example`.

## 3. Lanzamiento de Contenedores
Para construir y levantar el sistema:
```bash
docker compose up -d --build
```
*Esto levantará: `sgaf_db_prod`, `sgaf_backend_prod`, `sgaf_frontend_prod` y Nginx.*

## 4. Gestión de Datos (Restauración de Backup)
Para poblar el sistema con un respaldo (`.sql`) generado anteriormente:

1. Subir el archivo al servidor (vía SCP):
   `scp backup.sql user@ip:/home/user/`
2. Inyectar el respaldo en el contenedor:
   `cat ~/backup.sql | docker exec -i sgaf_db_prod psql -U sgaf_user -d sgaf_db`

## 5. Mantenimiento y Logs
Ver estado: `docker ps`
Ver logs: `docker compose logs -f`
Reiniciar: `docker compose restart`

## 6. ⏰ Automatización de Tareas (Cron)
El sistema incluye tareas en segundo plano que deben programarse en el host de Ubuntu:

### 1. Dar permisos a los scripts de automatización:
```bash
chmod +x scripts/*.sh
```

### 2. Configurar el Crontab:
Abre el editor de cron del servidor:
```bash
crontab -e
```

Agrega las siguientes líneas al final del archivo para programar las tareas automáticas:

```cron
# 1. Envío diario de recordatorios (Todos los días a las 08:30)
30 8 * * * /home/svtest/sgaf/scripts/enviar_recordatorios_diarios.sh

# 2. Limpieza de datos expirados (Ley 21.719 — Cada 1 hora)
0 * * * * /home/svtest/sgaf/scripts/cleanup_expired_data.sh

# 3. Respaldos automáticos de base de datos (Diarios a las 09:00 y 18:00)
0 9,18 * * * /home/svtest/sgaf/scripts/respaldo_automatico_sgaf.sh >> /home/svtest/backup_log.txt 2>&1
```
*(Nota: Ajusta la ruta `/home/svtest/` y el usuario en caso de haber descargado el proyecto en otro directorio).*
