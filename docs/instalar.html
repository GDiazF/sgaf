Primera instalación en el servidor

Ubuntu nuevo, sin SGAF. Cada paso explica qué hace y por qué es necesario.

Requisitos previos

Docker, Docker Compose y Git instalados en Ubuntu.

Por qué SGAF no se instala como un programa .exe: corre dentro de contenedores Docker orquestados por Compose, y el código se obtiene clonando el repositorio Git. Sin estas herramientas no hay forma de levantar el sistema. Detalle en docs/0. preparacion_servidor.md.

  1. Paso 1 — Descargar el código desde GitHub 
    cd ~
git clone -b reingenieria https://github.com/GDiazF/sgaf.git sgaf
cd sgaf
chmod +x scripts/*.sh scripts/lib/*.sh

    Clona la rama de producción y da permiso de ejecución a los scripts.

    Por qué El servidor empieza vacío: necesita una copia del proyecto. La rama reingenieria es la que se despliega en producción. chmod +x permite ejecutar deploy.sh y demás; sin eso Linux rechaza el script con “Permission denied”.

  2. Paso 2 — Crear configuración base (.env) 
    ./scripts/setup_env.sh

    Genera .env desde la plantilla y detecta IP/hostname del servidor.

    Por qué Django, PostgreSQL y firma-dep leen secretos y URLs desde .env (nunca van en Git). El script crea el archivo si no existe y rellena CORS, ALLOWED_HOSTS y URL pública según la red del servidor, evitando el error 400 al hacer login.

  3. Paso 3 — Completar secretos (una sola vez) 
    nano .env

    Editar contraseñas y claves que el script no puede inventar por usted.

    Por qué Cada instalación debe tener sus propios secretos únicos. Si dos servidores comparten SECRET_KEY o contraseñas de BD, un compromiso en uno afecta al otro. FirmaGob y firma-dep también requieren credenciales reales de la RA.

    VariableQué ponerPor qué
    SECRET_KEYTexto largo aleatorioFirma sesiones y tokens Django
    DB_PASSWORDContraseña PostgreSQLProtege la base de datos
    FIRMA_GOB_*Token y Secret de FirmaGobConexión con la autoridad certificadora
    FIRMA_DEP_API_KEYClave que usted eligeAutentica backend → firma-dep
    API_CLIENT_KEYSsgaf-backend: + misma claveDebe coincidir con FIRMA_DEP_API_KEY

    Nunca suba .env a Git.

  4. Paso 4 — Desplegar (levantar Docker) 
    ./scripts/deploy.sh

    Construye imágenes, inicia contenedores, crea tablas y archivos estáticos.

    Por qué Hasta este momento no hay SGAF corriendo: solo archivos en disco. deploy.sh ejecuta docker compose up --build, espera al backend, corre migrate (tablas iniciales) y collectstatic. Al final muestra la URL de acceso.

  5. Paso 5 — Crear usuario administrador 
    docker exec -it sgaf_backend_prod python manage.py createsuperuser

    Crea la primera cuenta con acceso total al sistema.

    Por qué La BD nueva no tiene usuarios. Sin un superusuario no puede entrar a SGAF ni al panel de administración para crear roles, funcionarios y permisos de firma.

  6. Paso 6 — Configurar respaldos en nube (recomendado)

    Programar copias automáticas a Google Drive con rclone y cron.

    Por qué Un respaldo solo en el mismo disco del servidor no protege si el servidor falla, se formatea o es robado. La nube + cron asegura copias periódicas sin depender de que alguien recuerde hacerlo manualmente. Ver Respaldos.

Sin setup_env.sh ni deploy.sh. Mismas etapas, ejecutadas manualmente.

cd ~

cd sgaf
cp .env.example .env

docker exec sgaf_backend_prod python manage.py collectstatic --noinput

docker compose ps
  1. Paso 1 — Clonar el repositorio 
    cd ~
git clone -b reingenieria https://github.com/GDiazF/sgaf.git sgaf
cd sgaf

    Obtener el código fuente en el servidor.

    Por qué Equivalente al paso 1 del modo script: sin el código no hay aplicación que desplegar.

  2. Paso 2 — Crear y editar .env 
    cp .env.example .env
chmod 600 .env
nano .env

    Copiar plantilla, restringir permisos y completar secretos y red.

    Por qué cp crea lo que haría setup_env.sh. chmod 600 limita lectura del archivo solo a su usuario (protege contraseñas). En nano debe completar secretos y URLs (ver tabla en Actualizar → Modo manual, paso 4).

  3. Paso 3 — Levantar contenedores Docker 
    docker compose up -d --build

    Compila y arranca frontend, backend, PostgreSQL y firma-dep.

    Por qué SGAF corre en cuatro servicios que deben estar activos y comunicados. -d los deja en segundo plano; --build construye las imágenes la primera vez.

  4. Paso 4 — Migraciones y archivos estáticos 
    docker exec sgaf_backend_prod python manage.py migrate --noinput
docker exec sgaf_backend_prod python manage.py collectstatic --noinput

    Crear tablas en PostgreSQL y preparar assets del admin.

    Por qué La BD del contenedor PostgreSQL está vacía: migrate crea todas las tablas Django. collectstatic deja listos CSS/JS del panel de administración.

  5. Paso 5 — Crear usuario administrador 
    docker exec -it sgaf_backend_prod python manage.py createsuperuser

    Primera cuenta con acceso al sistema.

    Por qué Sin usuario no puede iniciar sesión ni configurar roles, funcionarios ni firma digital.
